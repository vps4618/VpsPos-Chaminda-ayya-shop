	Things that made chatgpt code faster -->
		⚡ Why the new code is faster

			One database connection instead of many

				Old code (executeSqlCommand without transaction) → every query opened a new SqlConnection, executed, then closed.

				New code → opens one connection and runs all inserts/updates inside it.
				👉 Avoids repeated connection open/close, which is one of the slowest parts of database I/O.

			Transaction batching

				Old way → Each insert/update was autocommit (SQL Server commits each query separately).

				New way → All inserts/updates are grouped into a single transaction.
				👉 SQL Server only writes to disk once, instead of multiple times.

			Prepared commands with parameters

				Old way → Your code passed raw SQL strings → SQL Server had to re-parse and re-plan execution each time.

				New way → Uses SqlCommand + parameters → SQL Server can reuse execution plans.
				👉 Less parsing, less CPU overhead.

			Less network chatter

				Old way → Multiple round-trips between app ↔ database because each query opened/closed a connection.

				New way → One round-trip with multiple queries inside a single session.
				👉 Fewer packets, faster response.

			📊 Quick analogy

				Old code = Sending 10 separate letters to the post office, each time driving there, waiting in line, then going home.

				New code = Packing all 10 letters in one envelope, driving to the post office once, and sending them all together.
